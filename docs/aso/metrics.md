# ASO 지표 — 무엇을 보고, 어떻게 읽는가

> 목적: 문구를 바꿨을 때 **정말 나아졌는지** 판단할 수 있게 한다.
> 기록 없이 바꾸면 좋아졌는지 나빠졌는지 영영 알 수 없다.

---

## 0. 시작하기 전에 — 기준선부터 찍는다

**무엇이든 바꾸기 전에 현재 숫자를 먼저 캡처한다.** 이게 이 문서에서 가장 중요한 한 문장이다.
Play Console은 과거 데이터를 보여주지만, "그때 무엇을 바꿨는지"는 기록해 주지 않는다.

아래 [기록 템플릿](#5-기록-템플릿)에 **오늘 날짜로 한 줄 먼저 남기고** 작업을 시작할 것.

---

## 1. 어디서 보는가

| 지표 | 경로 |
|---|---|
| 스토어 방문자·설치·전환율 | Console → **사용자 확보 → 스토어 성과** |
| 유입 검색어 | Console → **사용자 확보 → 스토어 성과 → 획득 채널: 검색** |
| 유지율 | Console → **사용자 확보 → 유지** |
| 평점·리뷰 | Console → **품질 → 평점** |
| 크래시·ANR | Console → **품질 → Android vitals** |

> 데이터는 보통 **2~3일 지연**된다. 어제 바꾸고 오늘 판단하지 말 것.
> 설치 수가 적을 때는 **일 단위가 아니라 주 단위**로 본다 — 하루 3명이 5명 되는 건 노이즈다.

---

## 2. 핵심 지표 4개와 읽는 법

### 2-1. 스토어 방문자 수 (노출이 아니라 방문)

**의미**: 스토어 페이지까지 들어온 사람 수. **ASO 키워드 작업의 직접 결과**다.

- 이 숫자가 안 늘면 → **검색에 안 잡히는 것.** 제목·짧은 설명·키워드 문제.
- 이 숫자는 느는데 설치가 안 늘면 → **페이지가 설득을 못 하는 것.** 스크린샷·설명 문제.

**둘을 구분하는 게 이 지표의 존재 이유다.** 하나로 뭉쳐 보면 어디를 고칠지 알 수 없다.

### 2-2. 스토어 방문자 대비 설치 전환율 ⭐

**의미**: 페이지에 들어온 사람 중 설치한 비율.

```
전환율 = 설치 수 ÷ 스토어 방문자 수
```

**읽는 법 — 무엇과 비교할 것인가**

절대값의 "좋은 기준"을 외부에서 가져오지 말 것. 카테고리·국가·유입 경로에 따라 편차가
크고, 우리처럼 표본이 작을 때는 남의 평균과 비교하는 게 의미가 없다.
**비교 대상은 오직 우리의 지난주 숫자다.**

| 관찰 | 해석 | 할 일 |
|---|---|---|
| 방문 ↑, 전환율 유지 | 키워드가 먹혔다 | 그대로 두고 관찰 |
| 방문 ↑, 전환율 ↓ | **관련 없는 키워드로 유입 중** | 유입 검색어 확인 → 어긋난 키워드 제거 |
| 방문 유지, 전환율 ↑ | 스크린샷·설명이 먹혔다 | 같은 방향으로 더 |
| 방문 ↓ | 순위 하락 또는 계절 요인 | 순위·경쟁 앱 변화 확인 |

**⚠️ 전환율 ↓ 를 무조건 나쁘게 읽지 말 것.** 우리가 "연산 문제" 같은 넓은 키워드를
일부러 제외했기 때문에(→ [`store-listing.md`](store-listing.md) #16), 방문자 수는
덜 늘어도 **설치 후 남는 사람의 질**이 올라가는 게 정상 경로다. 그래서 다음 지표를 함께 본다.

### 2-3. 1일 / 7일 유지율

**의미**: 설치한 사람 중 다음 날, 일주일 뒤에도 앱을 여는 비율.

**ASO 문서에 유지율이 왜 있는가**: Play는 설치 후 바로 지우는 앱의 순위를 낮춘다.
**잘못된 키워드로 설치를 늘리면 순위가 오히려 떨어진다.** 유지율은 우리가 고른 키워드가
"맞는 사람"을 데려오고 있는지를 알려주는 유일한 신호다.

> **지금은 이 지표가 특히 중요하다.** v1.0.0에는 두 번째 문제부터 제출이 막히는 버그가
> 있어(→ PR #36), **1일 유지율이 구조적으로 낮을 수밖에 없다.**
> v1.0.1 배포 전후로 이 숫자가 어떻게 변하는지가, 그 버그의 실제 피해 규모를 알려준다.

### 2-4. 평점

설치 수가 적을 때 **평점은 가장 되돌리기 어려운 지표다.** 1점 리뷰 3개가 5점 리뷰 30개를
필요로 한다. 그래서 [`launch-plan.md`](../marketing/launch-plan.md)에서 홍보를
v1.0.1 이후로 미루는 것이다.

## 3. 보지 않아도 되는 것

시간을 아끼기 위해 **초기에는 무시해도 되는 것**:

- **노출 수(impressions)** — 방문자 수와 거의 같이 움직인다. 둘 다 볼 필요 없다.
- **국가별 분해** — 한국 외 유입이 유의미해지기 전까지는 노이즈.
- **일별 그래프의 요일 등락** — 주말에 늘고 평일에 주는 건 정상이다. 주 단위로 볼 것.

## 4. 언제 판단하는가

| 시점 | 무엇을 본다 |
|---|---|
| 변경 직후 | 심사 통과 여부만. 지표는 보지 않는다 |
| 3일 후 | 데이터 반영 시작. **아직 판단하지 않는다** |
| 2주 후 | 방문자 수 변화로 **키워드 효과** 1차 판단 |
| 4주 후 | 전환율·유지율로 **문구·스크린샷 효과** 판단 |
| 6주 후 | 유입 검색어로 [`store-listing.md`](store-listing.md)의 키워드 표 갱신 |

**한 번에 하나만 바꾼다**는 원칙을 지키면 판단이 쉬워진다. 제목·설명·스크린샷을 같은 날
다 바꾸면 무엇이 효과를 냈는지 알 수 없다. 다만 지금은 설치 수가 워낙 적어
**통계적으로 유의한 A/B는 어차피 불가능**하므로, 초기 1회는 한꺼번에 바꾸고
그 이후부터 하나씩 바꾸는 게 현실적이다.
