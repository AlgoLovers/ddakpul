## 2. 블로그 개발기 (1순위)

### 왜 먼저인가
커뮤니티 글은 하루 지나면 묻힌다. 블로그 글은 **검색으로 계속 유입된다.**
"초등 사고력 수학 앱 만들기", "적응형 학습 알고리즘" 같은 검색어로 몇 달간 들어온다.

### 어디에
- 개인 블로그(있다면) · 없으면 **velog** 또는 **티스토리**
- 개발 이야기는 velog가, 학부모까지 닿으려면 네이버 블로그가 유리하다
- **둘 다 쓰는 것도 방법** — 같은 내용을 톤만 바꿔서

### 무엇을 쓰는가 — 3편 구성 제안

**1편: 왜 만들었나 (학부모도 읽는 글)**
- 시중 초등 수학 앱이 대부분 연산 드릴인 이유와 그 한계
- "생각하는 문제"를 어떻게 정의했는지 (연습장 펴고 5분)
- 4개 영역, 난이도 1~10 설계

**2편: 추천 알고리즘 (개발자용)**
- 런타임 AI 호출 0원, 순수 규칙 기반으로 만든 이유(비용·오프라인·예측 가능성)
- 규칙 1~8 (`CLAUDE.md`의 추천 알고리즘 표)
- Leitner 간격 복습을 어떻게 넣었나
- 근거는 `docs/PEDAGOGY.md`

**3편: 문제 1,000개를 만든 방법 (개발자용, 가장 반응 좋을 글)**
- 생성 + 솔버 검증 파이프라인 (`/gen-problems`)
- 이중언어 불변식
- 난이도 캘리브레이션에서 겪은 실패

> 💡 **3편이 가장 널리 읽힐 가능성이 높다.** "문제를 자동 생성하고 솔버로 검증했다"는
> 개발자에게 흥미로운 주제이고, 자연스럽게 앱 링크를 넣을 수 있다.

### 규정
없음. 다만 **앱 링크는 글 끝에 한 번만.** 중간중간 넣으면 광고 글로 읽힌다.

## 3. 개발자 커뮤니티 (2순위)

### 어디에
- **GeekNews(news.hada.io)** — 개발기·기술 글에 우호적. 가장 추천.
- **OKKY**, **커리어리** — 한국 개발자 대상
- **r/androiddev** (영어) — 앱이 영어를 지원하므로 가능
- **Show HN** (Hacker News) — 영어권. 반응은 복불복이지만 비용 0

### 규정 주의
- GeekNews: 자기 글 제출 가능하나 **자기 홍보만 반복하면 제재.** 다른 글도 읽고 참여할 것.
- Reddit r/androiddev: **자기 홍보 전용 스레드**가 따로 있는 경우가 많다.
  서브레딧 규칙을 반드시 먼저 읽을 것. 어기면 계정 밴.
- 공통: **"제 앱 써주세요"가 아니라 "이렇게 만들었습니다"**로 접근한다.
  개발자 커뮤니티는 기술 내용이 있으면 관대하고, 없으면 냉정하다.

### 기대치
개발자 커뮤니티에서 오는 설치는 **직접적인 타깃이 아니다**(학부모가 아니므로).
그럼에도 하는 이유는 ① 초기 피드백의 질이 높고 ② 버그를 잘 잡아 주고
③ 그중 일부는 실제로 초등 자녀가 있기 때문이다.

## 4. 학부모 커뮤니티·맘카페 (3순위, 가장 조심할 것)

### ⚠️ 먼저 알아야 할 것

**맘카페는 대부분 앱 홍보를 금지한다.** 무료 앱이어도 마찬가지다.
"무료니까 괜찮겠지"는 통하지 않는다 — 카페 입장에서는 **트래픽을 가져가는 광고**다.

그리고 **아래 규정은 카페마다 전부 다르다.** 내가 특정 카페의 규칙을 확인해 준 것이
아니므로, **반드시 해당 카페의 "카페 규정" 게시글을 직접 읽고 시작할 것.**
일반적으로 자주 보이는 규정은 이렇다:

| 자주 보이는 규정 | 대응 |
|---|---|
| 가입 후 일정 기간·활동 이후에만 글쓰기 가능(등업) | 최소 2~4주 전부터 계정 활동 |
| 홍보성 글은 지정 게시판에만 | 게시판 성격을 먼저 확인 |
| 외부 링크 금지 | 링크 대신 앱 이름만, 또는 운영자 사전 문의 |
| 사업자·개발자 본인 홍보 전면 금지 | **이 경우 그냥 하지 않는다** |
| 첫 글이 홍보면 즉시 강퇴 | 활동 이력 없이 홍보 글부터 쓰지 않는다 |

### 가장 안전한 순서

1. **운영자에게 먼저 쪽지로 문의한다.** "개인이 만든 무료 앱인데 소개해도 되는지,
   된다면 어느 게시판이 맞는지" — 이 한 번의 문의가 강퇴를 막는다.
2. 허락받은 게시판에만, **한 카페에 한 번만** 올린다.
3. 여러 카페에 같은 글을 도배하지 않는다. 맘카페 이용자는 겹치는 경우가 많아 금방 들통난다.
4. 댓글 질문에는 성실히 답한다. **이게 실제 설치로 이어지는 부분이다.**

### 대안 채널 (규정 위험이 낮은 곳)

맘카페가 막히면 이쪽이 낫다:
- **네이버 블로그** — 학부모가 "초등 사고력 수학 앱"으로 검색해 들어온다
- **인스타그램** — 스크린샷 중심. 육아·홈스쿨링 해시태그
- **아이 학교·학원 학부모 단톡방** — 지인 기반. 다만 아래 "지인 공유" 주의사항 참고
- **홈스쿨링·자기주도학습 카페** — 앱 소개에 상대적으로 관대한 편

## 5. 커뮤니티용 글 초안

### ⚠️ 쓰기 전에 — 사실이 아니면 쓰지 말 것

아래 초안은 **"아이를 위해 직접 만들었다"는 서사**를 전제로 쓰였다.
**이게 사실이 아니라면 이 초안을 쓰면 안 된다.**

이유는 윤리 때문만이 아니다. 맘카페에서 지어낸 서사는 **높은 확률로 들킨다**
(댓글로 아이 나이·학년을 물어보고, 답이 어긋나면 바로 의심받는다).
들키는 순간 앱까지 같이 매장된다.

`[대괄호]` 부분은 **직접 채우거나, 채울 수 없으면 그 문장을 통째로 지운다.**
사실인 부분만 남겨도 글은 충분히 성립한다.

### 5-1. 맘카페·학부모 커뮤니티용 (링크 허용 시)

```
초등 수학 문제집을 앱으로 만들어 봤어요 (무료, 광고 없음)

안녕하세요. [아이 학년/상황 — 예: 초3 아이 키우는] 학부모이자 개발자입니다.

아이가 연산은 곧잘 하는데 조금만 문장이 길어지면 손을 놓더라고요.
문제집을 사 줘도 몇 장 풀다 덮어 두기 일쑤였고요.
[※ 이 문단은 실제 경험이 아니라면 지우세요]

시중 앱을 여러 개 깔아 봤는데, 대부분 연산 반복이거나 중간에 광고가 뜨거나
결제를 유도하더라고요. 그래서 직접 만들어 봤습니다.

만들면서 정한 원칙은 세 가지였어요.

1. 계산 반복은 넣지 않는다
   연습장 펴고 5분쯤 생각하는 문제만 담았어요.
   규칙 찾기, 도형 세기, 조건 따지기 같은 것들이요.

2. 학년으로 나누지 않는다
   같은 3학년이어도 실력이 다 다르잖아요.
   난이도 1~10단계로만 나누고, 아이가 푸는 걸 보고 다음 문제를 골라 줍니다.
   맞히면 조금 더 어렵게, 틀리면 한 걸음 뒤로요.

3. 아이에게 보여주고 싶지 않은 건 안 넣는다
   광고 없고, 결제 없고, 회원가입도 없어요.
   학습 기록은 휴대폰 안에만 저장되고 밖으로 나가지 않습니다.
   비행기 모드로도 다 됩니다.

문제는 1,000개가 조금 넘고, 모든 문제에 단계별 풀이가 있어요.
틀린 문제는 오답 노트에 모여서 나중에 다시 풀 수 있고요.
부모용 리포트에서는 네 영역 중 어디가 강하고 약한지 볼 수 있습니다.
[화면이 지겨울 땐 A4로 인쇄해서 종이로 풀 수도 있어요.]

혼자 만든 거라 부족한 점이 많을 거예요.
써 보시고 이상한 점 있으면 알려주시면 고치겠습니다.

플레이스토어: [링크]

※ 운영자님, 홍보성 글로 보이면 삭제해 주세요. 사전에 문의드리고 올립니다.
```

**이 초안의 설계 의도**
- 제목에 "무료, 광고 없음"을 넣어 **경계심을 먼저 낮춘다**
- 원칙 3가지가 곧 [`store-listing.md`](../aso/store-listing.md)의 차별점과 같다 — 메시지 일관성
- "부족한 점이 많을 거예요"로 **완제품을 파는 톤을 피한다.** 맘카페에서 가장 잘 먹히는 태도다
- 마지막 줄로 **운영자에게 미리 양해를 구한다** — 삭제되더라도 강퇴는 면한다

### 5-2. 개발자 커뮤니티용

```
초등 사고력 수학 앱을 만들었습니다 — 런타임 AI 호출 0원, 완전 오프라인

개인 프로젝트로 안드로이드 학습 앱을 만들어 출시했습니다.
기술적으로 재미있었던 부분을 공유합니다.

■ 왜 AI를 안 썼나
문제 추천에 LLM을 쓰면 사용자당 비용이 계속 나가고, 오프라인이 안 되고,
같은 입력에 다른 답이 나옵니다. 아이가 쓰는 학습 앱에는 셋 다 치명적이라
순수 규칙 기반으로 짰습니다. 8개 규칙(연속 정답 승급, 연속 오답 강등,
정체 감지, Leitner 간격 복습 등)이 전부 순수 함수라 단위 테스트로 고정돼 있습니다.

■ 문제 1,000개를 어떻게 만들었나
손으로 135개를 쓰고 나서 이 방식으로는 못 채우겠다 싶어서,
생성기 + 솔버 검증 파이프라인을 만들었습니다.
생성한 문제를 솔버가 실제로 풀어서 정답이 맞는지 검증하고,
통과한 것만 문제은행에 들어갑니다. 한/영 이중언어 불변식도 같이 검사합니다.

■ 구조
Kotlin / Compose / Clean Architecture 3계층 / Hilt / Room.
domain 계층에 android import를 금지하는 규칙을 테스트로 강제하고 있습니다.
(리뷰로만 지키려니 결국 새더군요)

■ 결과물
[플레이스토어 링크]
무료, 광고 없음, 오프라인 동작합니다.

피드백 주시면 감사하겠습니다. 특히 문제 난이도가 이상하다 싶은 게 있으면
앱 안에서 바로 신고할 수 있게 해 뒀습니다.
```

**의도**: 기술 내용이 앞에 오고 링크는 뒤에 있다. 개발자 커뮤니티에서 이 순서가 뒤집히면 무시당한다.

## 6. 초기 리뷰 확보

### ❌ 하면 안 되는 것 (Play 정책 위반)

- 리뷰 대가로 보상·아이템·현금 제공
- 지인에게 **별점을 지정해서** 요청 ("5점 주세요")
- 리뷰 구매, 대행 업체
- 부정 리뷰를 상쇄하려 가짜 계정으로 작성

**적발 시 앱 삭제·계정 정지까지 간다.** 초기 다운로드 몇 개와 바꿀 것이 아니다.

### ✅ 해도 되는 것

**1. 앱 안에서 리뷰 요청 (가장 효과적, 현재 미구현)**

Google의 **In-App Review API**를 쓰면 앱을 벗어나지 않고 리뷰를 남길 수 있다.
현재 딱풀에는 **구현돼 있지 않다** — 소스에서 확인했다.

- **요청 타이밍이 전부다.** 좋은 순간: **하루 목표를 달성한 직후**
  (`goalJustReached`가 이미 상태로 있다 → `SolveUiState`)
- 나쁜 타이밍: 앱 시작 직후, 문제를 틀린 직후
- API 제약: 사용자당 노출 횟수에 쿼터가 있어 남용이 구조적으로 불가능하다
- **별점을 지정해 요청하지 않는다.** 그냥 리뷰 화면을 띄우기만 한다

> 이건 코드 작업이 필요하다. v1.0.2 후보로 백로그에 넣을 것.

**2. 솔직한 후기 요청 (별점 지정 없이)**

지인·커뮤니티에 이렇게 요청하는 것은 정책 위반이 아니다:

```
써 보시고 괜찮으셨으면 플레이스토어에 솔직한 후기 남겨 주시면 큰 힘이 됩니다.
불편했던 점을 그대로 적어 주셔도 좋습니다 — 그게 더 도움이 돼요.
```

**"솔직한", "불편한 점도"** 라는 표현이 핵심이다. 별점을 지정하지 않는 한 정당하다.

**3. 부정 리뷰에 답글 달기**

Play Console에서 리뷰에 답글을 달 수 있다. **낮은 별점에 성실히 답하면
별점을 올려 주는 경우가 실제로 있다.** 새 방문자에게도 "관리되는 앱"으로 보인다.

- 24~48시간 내 답글
- 변명하지 않고, 고칠 것은 언제 고치겠다고 명시
- 고쳤으면 다시 답글로 알린다

## 8. 현실적인 기대치

**정직하게 적어 둔다.** 개인 개발 앱이 홍보 몇 번으로 폭발하는 일은 거의 없다.

- 블로그 글 1편이 잘 되면 **수십~수백 방문**, 그중 설치는 한 자릿수~십여 건
- 맘카페 글 하나가 잘 되면 **수십 설치**, 대부분은 그보다 적다
- **꾸준한 유입은 결국 ASO(검색)에서 나온다** — 홍보는 초기 종잣돈이고,
  검색 순위가 오르기 시작하면 그쪽이 훨씬 크다

그래서 이 문서의 실제 목적은 "폭발적 성장"이 아니라
**① 첫 리뷰 몇 개를 확보하고 ② 실사용 피드백을 받아 앱을 고치고
③ 검색 순위가 오를 최소한의 초기 신호를 만드는 것**이다.
