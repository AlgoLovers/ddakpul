## 1. 판정 원칙 (입문층 헌법 — 감사 때 이 기준으로 재검증)

- **d1: 구구단·나눗셈·받아내림 금지.** 허용 도구는 세기·한 자리 덧뺄셈·직관 비교·패턴 인식뿐.
  d2: 두 자리 덧뺄셈·간단한 규칙 찾기까지. 곱셈구구 전제는 여전히 금지(나열로 우회 가능해야 함).
- **해설 언어도 같은 층이어야 한다**(감사 §6): d1 해설에 ×·÷ 표기 금지. "2씩 3묶음",
  "반씩 나누면" 같은 세기 언어로 쓰고, 필요하면 곱셈식을 *괄호 병기*만 한다
  (모범: `g-gen-outfit-1` "표를 그려 하나씩 짝지어도 6가지").
- 사고력 원칙 불변: 계산 드릴 금지, 낮은 문턱·높은 천장. d1이라도 "세면 나온다"가 아니라
  "**무엇을 셀지 스스로 정해야** 한다"가 문턱이 되게.
- 4지선다·정답 유일·오답은 식별 가능한 오개념에서. 전 문항 브루트포스 검산 짝.

- 기존 저층 family와의 '사실상 중복' 주의 — checks.py 게이트5. 특히 cubetiny·gridtiny·dataread·

## 3. 순서 (감사자 이견 반영, 2026-08-01)

1. **동형 중복 4쌍은 하향이 아니라 병합/제거 건 — 먼저 처리한다.**
   cubestackeasy↔cubetiny, grideasy↔gridtiny, barchart↔dataread, case2-01↔outfit-3.
   단순 하향하면 d1에 사실상 같은 문제가 두 그룹씩 생기고, 규칙5(하루 중복 금지)는 id 기준이라
   같은 문제를 하루 두 번 낼 수 있다 — 난이도 정합성이 아니라 **앱 동작 문제**.
2. 감사 2차 적용은 **상향 잔여(29)와 하향(23)을 같은 배치에서 함께** — 상향은 층 재고를 깎고
   하향은 채우므로 따로 하면 층이 일시적으로 얇아진다. 특히 `cards` d1→d2는 d1 수와연산이
   3그룹 11문항뿐이라 **신규 재고 확보 후**에만(안 그러면 4영역 균형이 best-effort로 떨어짐).
3. 이 문서 family를 `/gen-problems`로 구현(검산 짝 + en 짝 + 게이트 통과) → 분포 재측정.
4. problem-auditor 재감사(§1 헌법 기준) → CONTENT_VERSION 범프 → 릴리스 노트에 "쉬운 문제 확충" 기재.
